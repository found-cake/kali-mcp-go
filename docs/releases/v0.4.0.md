# Kali MCP v0.4.0

This release moves the recommended Docker setup to a persistent, isolated runtime and expands the MCP result, evidence, target-resolution, safety-profile, capability, and background-job contracts used by security-testing agents.

## Highlights

- Raw shell and PowerShell installers create one managed container and register clients through `docker exec`.
- Installer reruns pull the selected image and replace an outdated managed container while preserving unmanaged containers.
- Scan results expose structured execution, finding, request-count, progress, provenance, and artifact metadata.
- Large process output is bounded, and sensitive result artifacts expire independently after one hour.
- Long-running asynchronous results remain available for the requested execution timeout plus a three-minute grace period.

## Migration notes

- Replace one-shot Docker MCP launchers with the Raw installer for your platform, then register the printed `docker exec` command. The installer refuses to replace a container it did not create.
- For a loopback target, call `resolve_target`, select the reachable Docker-host candidate, and reuse its `target_context` until it expires.
- Pass cookies, authorization headers, and browser local storage with each relevant call. Kali MCP does not retain reusable credential sessions.
- Review scanner arguments against `get_scan_capabilities`; safety profiles now reject conflicting destinations, unsupported controls, and higher-impact options more consistently.
- Read large retained results through `result_artifact_read` with pages no larger than 65,536 bytes.
